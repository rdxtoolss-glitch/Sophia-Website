Privacy & Data Protection

Privacy Policy for Sophia AI

Effective Date: October 2026 | Operator: Muhammad Junaid, Mobo Devs Studio (mobodevs.net)

Muhammad Junaid and Mobo Devs Studio ("we", "our", or "us"), operating under mobodevs.net, are committed to uncompromising user privacy and data sovereignty for every user of the Sophia AI Voice Assistant Windows desktop application ("Sophia", "Software").

This Privacy Policy describes what information is processed, how it is safeguarded on your local machine, and how we strictly adhere to the Google API Services User Data Policy regarding Google OAuth 2.0 authentication and Google Workspace tools.

1. Purpose of Sophia AI

Sophia AI is an autonomous desktop conversational voice assistant for Microsoft Windows 10 and 11. It executes local desktop tasks (WhatsApp calling and messaging, Visual Studio Code dev tooling, high-speed Word document typing, window management, screen perception) through real-time voice streaming and 9 specialized Windows desktop capabilities.

2. Google OAuth 2.0 Authentication & Workspace Data

Sophia AI integrates optional Google OAuth 2.0 ("Sign in with Google") to verify the desktop user's identity and power optional Google Workspace tools (Calendar, Tasks, and Gmail drafts).

When you choose to authenticate via Google, we process the following data:

  • OpenID Profile Information: Full name, verified email address, and avatar URL to display within the desktop settings modal and personalize vocal greetings.
  • Optional Google Workspace Scopes: If you explicitly ask Sophia to interact with your Google Calendar (e.g. "What's on my schedule today?"), Google Tasks ("Add a task to buy groceries"), or Gmail ("Draft an email in Gmail"), Sophia interacts via official Google REST APIs using your locally stored OAuth refresh tokens.

Zero Cloud Transmission: Sophia AI does not upload your calendar events, emails, tasks, or contacts to remote third-party servers. All tokens reside locally in %APPDATA%\Sophia\data\google_tokens.json encrypted with Windows DPAPI.

3. How Your Data is Stored & Processed (Local-First Sovereignty)

Sophia is architected under strict Local-First Sovereignty principles:

  • All authentication tokens, profile details, persistent memories, and user preferences are stored exclusively on your physical Windows computer under %APPDATA%\Sophia\data.
  • Local SQLite databases (sophia.db) are protected using the Windows Data Protection API (DPAPI), which cryptographically ties encryption keys to your Windows user logon account.
  • We operate zero centralized databases that record your voice conversations, transcripts, or keystrokes.
  • Voice audio is streamed in real time for conversational understanding and is processed ephemerally in RAM without persistent recording.

4. Data Sharing & Third-Party Disclosure

We hold a strict zero-data-monetization policy:

  • We NEVER sell, rent, lease, or trade your personal information or Google user data to third parties.
  • We do not share user data with advertising networks, data brokers, or marketing platforms.
  • We do not use Google user data to train generalized artificial intelligence models.

5. Google API Services User Data Policy Compliance

Sophia AI's use and transfer to any other app of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

6. How to Revoke Access or Delete Data

You retain total control over your credentials and local data at all times:

  • In the Desktop App: Open Sophia Settings > Profile and click "Sign out". This immediately purges your local session tokens.
  • Via Google Account: You can revoke Sophia AI's access at any time by visiting your Google Security Dashboard at https://myaccount.google.com/permissions.
  • Complete Data Deletion: Deleting the %APPDATA%\Sophia directory permanently removes all locally stored data, memories, and tokens from your machine.

7. Security Safeguards

We employ robust industry-standard safeguards including HTTPS/TLS 1.3 encryption for OAuth token exchanges, Content Security Policies (CSP) to block unauthorized remote script injections, and Windows DPAPI hardware-tied encryption for local SQLite databases.
